## Top priorities (from prompt.md)

1. Recipient surprise-envelope experience
2. Realistic finger-controlled page folding
3. Beautiful occasion-specific templates (digital magazine style)
4. Easy personalization
5. Genuinely offline interactive download

## Functional vs placeholder

Scaffold only: Next.js 15 + TS + Tailwind 3 config, folders, `.env.example`, placeholder home page. Not installed or compiled (no network in the build sandbox). `prompt.md` is a PLACEHOLDER: the brief was missing from the zip.

## Decisions made

- Scope: just a digital gift flipbook; do not over-engineer. Target 3,000 to 5,000 lines (was 23,000, then 7,000, then 3,500 before advanced controls)
- No sign-up or sign-in; hashed secret edit token, reopen via `/create?edit=<token>`; separate recipient token
- Three routes: `/`, `/create`, `/g/[token]`; Send is a popup on Create
- Templates are digital magazines. **Layouts are data:** about 24 slot-based layouts drawn by one generic renderer; each template = theme + 6 to 8 pages using those layouts
- **Advanced page controls (added 2026-10-03), all optional in a collapsed Customize panel:** layout picker per page; text font/size/alignment/color from theme presets; photo pan, zoom, fill/fit, filter, frame; add/duplicate/delete/move pages and background color; book palette and font-pair presets
- Edit screen is a flat, tap-to-select page editor with a thumbnail strip; Preview toggle uses the real fold engine
- One `gifts` table with JSONB content
- Offline export is one self-contained HTML file
- Engine: single-page layout only; independent of the app in `src/engine`
- Stack as in `prompt.md`

- **Fold engine accepted (2026-10-04):** user finger-tested the demo on a real phone and confirmed the fold works perfectly. Keep the current feel: 38% release threshold, ease-out 420/300 ms, no flick-velocity completion, current arrows. Do not retune unless a later test shows a problem.

- **Every page has at least one photo** (rule added 2026-10-03; all layouts include a photo slot; demo updated)

- **Full-screen reading mode:** the book fills the viewport when opened (fixed layout plus Fullscreen API where supported; iPhone Safari uses the fixed layout only). Added 2026-10-03; demo updated.

## Trade-offs accepted

- Controls are presets and steps only (no free-form drag or resize, no custom fonts, no undo/redo)
- Estimate is near the 5,000-line ceiling; trim levers: drop photo filters, drop page reordering, reduce layout count to about 16
- No rate limiter; relying on size caps and signed uploads (add later if abused)
- No automated tests beyond manual checks
- Losing the edit link or browser data loses edit access; popup must show it clearly

## Open decisions

- [x] Sample photo sourcing: generated placeholders (task 2.4)
- [x] Font loading in the app: `src/app/fonts.ts` imports `@fontsource/*` latin CSS (weights 400/600/700/800/900 where the family has them, plus italic 400); browsers fetch a file only when used. `loadFonts(fontPair)` in `src/lib/pages/fonts.ts` must be awaited before any canvas draw. The offline export (6.1) still embeds the chosen pair as base64 woff2.
